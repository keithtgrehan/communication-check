# Communication Check demo — approximately 75 seconds

Use only the three built-in fictional examples. Keep browser zoom at 100% for
capture; use a separate mobile screenshot to show the responsive layout.

**0–12 seconds — Problem.** “After a customer onboarding call, the follow-up can
sound clear to its writer while leaving the customer unsure what happens next.
Communication Check gives that draft a small, focused review.”

**12–30 seconds — Show a finding.** Load “Promises to confirm” and select Check
draft. “It quotes the original wording and asks me to confirm a strong product
commitment. It cannot know what was agreed, so it leaves the decision with me.”
Select “Select in draft” to show the exact evidence.

**30–48 seconds — Edit and recheck.** Replace the guarantee with “We are checking
whether the integration can be ready by Friday.” “Editing clears old findings.
I recheck the current wording; the product never rewrites or sends the email.”
Select Recheck draft, then Copy draft.

**48–60 seconds — Other examples.** Load “Too many asks,” run a check and show the
review prompt. Then load “Clear next steps” and show its empty result. “No flags
means these rules found no issue. It does not mean the email's facts are verified.”

**60–75 seconds — Limits and next step.** “The rules run in this page. Runtime
checks cover draft transmission and persistence; the small fictional evaluation
is engineering evidence, not customer validation. Next are three usability
sessions and five AM/CSM pilots.”

Show only verified counts from docs/EVALUATION.md and docs/VERIFICATION.md if
adding result captions. Do not turn a failed first run into an unstated success.
