## Exact first finding

**Quote:** “We guarantee that the custom integration will be ready by Friday.”

**Question:** “Has the responsible person or team confirmed this commitment, including any conditions or dependencies?”

**Selection:** original sample characters 85–150, end exclusive (browser UTF-16 positions).

## Tone example

**Finding:** Extra pressure in this request.

**Quote:** “Please send the name of your technical contact by Wednesday, 16 September so I can include them in the setup discussion, no more excuses.”

**Collaborative question:** “Could this wording overlook a real blocker? Would asking the customer to explain help?”

**Warm question:** “Would leaving room for the customer to explain the situation suit this follow-up?”

## Presenter-supplied revision — 297 characters

Copy only the following text, without the code fences or an extra final newline:

```text
Hi Sam,

Thanks for the setup discussion.

Please send the name of your technical contact by Wednesday, 23 September. Once I have the name, I will invite them to the setup discussion.

I will ask our integration lead to confirm feasibility and timing before we agree a delivery date.

Best,
Morgan
```

This prewritten example is not a spontaneous authorship claim or a verified real-world commitment. A real writer must agree an appropriate deadline and own the follow-up actions.

## 75-second version

- **0–15s:** “After onboarding, a follow-up can leave the customer unsure what happens next. This prototype explores a short review step before sending.” Run **Try a sample review**.
- **15–35s:** Show the exact guarantee and confirmation question. “It asks me to check the commitment; it does not know what was agreed.” Select **Edit this wording**.
- **35–55s:** Paste the complete revision, select **Recheck draft**, then **Copy draft**. “I supplied this revision. Editing clears the reviews; I have rechecked clarity here. No flags does not verify facts. Copy takes the current text.”
- **55–75s:** “I directed the scope and AI-assisted build; agents implemented it. Local rules need no runtime model, but coverage is limited and customer usefulness is unvalidated.”

The short version omits tone/style and Keep/Undo. It rechecks clarity only and must not claim both lenses were rechecked.

## Fallbacks and objections

**Page unavailable:** show the packaged desktop screenshot. Say it is a captured fictional example, not live execution. Walk through the quote and question; do not imply the current request ran.

**Clipboard denied:** follow the app's existing manual-copy guidance, select the current draft and copy manually. Acknowledge the fallback.

**Unexpected result:** explain limited coverage. Return to the disclosed curated example without claiming comprehensive detection. Report a changed result instead of modifying the app.

**Why not an LLM?** Local rules make this prototype inspectable and avoid a model/API dependency or transmitting drafts to a checking provider. They have weaker language coverage. Comparative usefulness against an LLM was not tested.

**Is this RevOps automation?** No. It explores owners, handoffs and dependencies; it does not integrate a CRM or run a revenue workflow.
